## This source-only V14 diagnostic

A **strictly keyless, public-only** GitHub PR workflow retrieves **two separate full HTTPS originals** from `https://www.lrl.mn.gov/legdb/senate_dir`, requiring exact known official host and path, no HTTP redirects, text/html, 5-MiB streaming byte bound and exact official LRL service-directory parser/provenance checks on *each*. It computes each **raw body SHA-256** independently. Within ephemeral memory only it also constructs a canonical list of **2024-year-overlapping named Senate persons and all their official qualifying term start/year-end/district tuples**, sorted by name and term; it hashes the entire canonical service-facts projection with a domain-separated schema prefix. No original names, HTML, member lists or term rows are printed or uploaded; only an original-body digest, canonical projection digest, 2024 roster count, source sizes, and equality booleans are emitted.

If the two original raw-body SHAs differ **but** the full year-2024 service projection digests are exactly equal, that is bounded affirmative evidence that unrelated live HTML differences do not alter the source facts used for name matching. If the year-service projection differs, or either full original is unavailable/unparsed, the public job **fails closed with a static phase**, not with any name, source row, or inferred senator identity. Synthetic regression tests demonstrate that row order or unrelated raw HTML SHA/size changes do not alter the digest, while a changed 2024 member name, term district, missing/duplicated person or unsafe provenance does.
