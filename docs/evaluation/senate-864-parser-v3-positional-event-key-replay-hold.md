# Issue #864 — historic Senate committee positional event-key replay blocker

**Audit scope:** 2021–2025 Minnesota Senate **committee** Minutes and named/count-only recorded source actions only. This is a non-writing review checkpoint, **not** a migration proposal, database repair or historical as-of/serving change.

The independently original-source-SHA-reverified 2022–25 linked electronic Minutes corpus has **1,452 PDFs** and the parser v3 yields **112** named source action candidates versus **104** with the frozen earlier parser: **eight added candidates**, five in 2024 and three in 2025. These are *source parser candidates*, not eight certified absent stored votes. The [verified original Education Policy February 14, 2024 PDF](https://www.lrl.mn.gov/archive/minutes/senate/2024/educ/20240214/educ_20240214_Minutes.pdf) contains **six separate numbered amendment decisions**, each with **the same ten named YEA/NAY fingerprints** but a distinct named original motion. Frozen parser v2 recognized only two candidates in that PDF. Official original re-acquisition and 16-shard source proof are in [run #38297462724](https://github.com/killjoy00/votepredict/actions/runs/38297462724) and the permanent [#864 original-PDF receipt](https://github.com/killjoy00/votepredict/issues/864#issuecomment-6131204094).

## Verified legacy write-path risk (not a claim of actual database corruption)

[The historical Senate backfill script](../../scripts/backfill-senate-committee-minutes.ts) generates a persisted `vote_events.external_key` as `senate-committee:<SHA256(source URL) first 16 chars>:<parser observationIndex>`, and uses **`ON CONFLICT(session_id,chamber_id,external_key) DO UPDATE`** on that key. Separately, per-person evidence `ingestionIdentityKey` includes `obs:<observationIndex>`, and `member_votes` uses an `ON CONFLICT` upsert. This creates a **credible replay / positional key collision hazard whenever parsing additions move existing positions**. Same ten-member vote slates are not six identical motions, so a member-choice fingerprint is not a stable action identity.

The current SHA-verified source audit establishes `2 -> 6` observed Education actions. It does **not** independently establish which two numbered actions were previously stored, their precise legacy original motion anchors, or whether a given live persisted positional event key would collide with a different motion under parser v3. **Do not claim proven corruption or eight missing database events.** The synthetic [regressions](../../tests/senate-864-positional-event-key-risk.test.ts) demonstrate two possible cases: four appended actions where positional collision count is unknowable without the old original action anchors, and four inserted actions where an existing index would denote another motion. Even unchanged source order cannot by itself certify a private historical row-to-motion match.

The pure [non-writing replay-risk verifier](../../src/evidence/senate-864-positional-event-key-replay-risk.ts) requires original PDF SHA proof, known action counts and strictly unique, explicitly supplied source motion anchors before calculating candidate index reuse. It exposes **numeric risk only**; its outputs **always withhold re-backfill/rekey authorization**. Unknown prior original motion anchors remain a source/action join HOLD, never `zero` collisions. The actual historical script's vulnerable positional key and SQL conflict update are pinned by an offline test so future changes cannot silently erase or relabel the recognized risk.

## Next permission-separated resolution

A further **separately reviewed protected bounded READ ONLY source-to-stored event audit** must compare all newly recognized original motions against actual current stored source PDF hashes, meeting-day metadata, old `vote_events` keys, original signed motion anchors and individual name-choice groups **in protected memory**. It must classify independent original actions versus duplicate/overwritten/ambiguous stored actions *without exposing* private names, source URLs, IDs, choice digests, or production identities. If old source manifests never retained enough original motion anchors to prove the old 2/6 action association, **HOLD** until independently reverified historical originals and stored event motion text supply them.

Only after this review and **separate owner authorization** may a dedicated migration/backfill be designed. Do not manually rerun parser-v3 2022–25 historic ingestion with positional external keys. No code in this checkpoint issues SQL, alters the existing importer, touches original evidence receipts or the database, or activates model/training/serving/scheduler/2027 tasks.
