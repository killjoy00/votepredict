## Three requested reconciliations

**1. Official filing versions against stored source evidence.** Replays all **830 currently indexed**, whole-PDF-SHA-verified original/amended candidate-committee PDFs (813 distinct bodies). Strictly matches a persisted source document only when its **full official viewer URL or full PDF SHA** matches the original government's exact record. Separately checks candidate registration/report YEAR representation in bulk evidence; that weaker match **never** certifies that an exact original/amended PDF version is stored. 830 is not a legally required original-report denominator.

**2. Contributions and expenditures, independently.** Scans persisted 2021–25 evidence from candidate-contribution bulk, candidate-expenditure bulk, independent-expenditure bulk and the mixed legacy finance family. Requires both the source kind and row subtype. Emits four non-overlapping categories: candidate contribution, candidate expenditure, independent expenditure, or subtype/source-kind mismatch. Keeps separate Senate membership-linked evidence vs metadata-only Senate claims. Outputs only per-year/category source copies, distinct row key counts, missing key counts, and committee-registrations counts. Does not add expenditures, IE, PAC, lobbying or party-unit activity to candidate contributions or invent transaction-to-PDF reconciliation.

**3. Historical eligibility against the newly dated inventory.** Counts preexisting stored as-of-eligible claims, legacy/unversioned eligibility policy, filing-derived claims, archived original-source claims, missing due dates and missing date fields. Compares a stored published/availability day against the **legal due-release floor** and separately the **V46 estimated availability day** ONLY where the persisted record explicitly cites the exact PDF-version ID, same registration and year. Never infers an amended/original report link from a bulk transaction date or candidate/year alone. A V46 day-level estimate is context, not authenticated exact historic first-public proof, and **does not automatically change stored historical model eligibility**.

## How the protected comparison runs

A no-secret pull-request job independently verifies all 830 original source identities, exercises safe aggregate shape tests and compiles all **four fixed SELECT queries** against a clean disposable PostgreSQL schema. After reviewed code reaches main, a separate pre-secret job reruns local migrations, SQL compile, complete app checks and production-dependency audit. Only if it passes, the protected existing-Neon-default-branch connection opens a **REPEATABLE READ READ ONLY** transaction, runs fixed bounded SQL and **ROLLBACK**, with credentials retained in the runner. The final keyless job posts integer-only per-year/family counts to issue #864. No per-person, donor, vendor, monetary, private row-key/DB identifier or credential logs are produced.
