## V15 new, separately reviewed one-shot rule

V15's unprivileged pre-secret job first authenticates the same **21 original government Minutes/OCR SHA-pinned metadata artifacts** and all normal existing CI and dependency gates. It then acquires and independently verifies **two complete official Senate directory HTML originals**, each requiring official HTTPS origin/path, no redirects, HTML content, 5 MiB cap, actual full-body SHA and the reviewed official LRL parser. It hashes *every year-2024-overlapping name and all its Senate start-year/end-year/district term tuples* using the separate domain-separated canonical-service schema from V14. Both original canonical digests and roster counts must be equal; the job exposes only the canonical 2024 service digest as an ephemeral SHA-valued Actions output, never directory names, HTML or raw vote evidence.

A new **first-attempt, exact reviewed main SHA** inside the existing `evidence-readonly-sandbox` is then permitted to reuse **unchanged three bounded original source/event/member-choice SELECTs**, the fixed <=30 direct name/alias probe and fixed <=150 2023–24 MN Senate historical roster SELECT within one `REPEATABLE READ READ ONLY` transaction with explicit `ROLLBACK`. It independently re-fetches the single source 2024 Minutes PDF in at most three attempts, verifies the exact frozen original raw PDF SHA, extracted-text SHA and unique original missing YEA fingerprint only inside protected memory. It next authenticates a **new, separately complete official LRL directory HTML**, obtains its independent raw SHA and official parser provenance, and compares its **exact canonical 2024 name+term+district projection SHA** against the independently verified pre-secret digest. A different semantic digest or unavailable original is a static HOLD, never a weaker match. Only then may the existing conservative historic backfill resolver evaluate the 2024-year-overlapping **official Senate directory** as a distinct source family.

This is deliberately **NOT a claim that any two original HTML raw SHAs are identical**. The complete raw originals can differ, and the approved [33-field safe V15 receipt](../../src/evidence/senate-864-2024-yea-v15-lrl-semantic-safe-scalars.ts) requires the three *separate* booleans:

`originalLrlRawHtmlByteEqualityNotClaimed=true`.

Its separate **keyless** issue receiver independently enforces all 33 scalar names, frozen one-missing-YEA/V10 read-only counts and all 20 static phase names; unexpected phase data is printed only as `unclassified`, never echoed.
