# Issue #864 — Date every campaign statement, and name actual Minnesota senators only

**Rules for the senator-facing source research ledger:**

1. A named person belongs here **only after independent proof of actual service in the Minnesota Senate**. Election candidacy/winning a race is not enough; an earlier/later losing race is not disqualifying if that person verifiably served in the Senate at another time.
2. **Every campaign issue-position source has a date backed by observed source evidence**, at minimum its independently recorded 2026-10-10 acquisition date. Dates printed on modern articles, an election date, or a candidate's later recollection are **not** backdated 2022 evidence.
3. **A historical public-by for specific words** is admitted only from real, original archived HTML bytes plus an independent historical index digest/capture timestamp. Even then, the source proves the words were present *no later than capture*, not the first time the campaign authored them.
4. All records remain **research evidence leads**. No retrospective winner status or source quote is automatically promoted to a model, historical feature, or database record.

## Actual independent Senate service and dates

The source qualification uses original **Minnesota Legislative Reference Library Senate service directory** HTTP 200 HTML saved in [verified source run #38094976711](https://github.com/killjoy00/votepredict/actions/runs/38094976711), artifact \`11685387674\`. An actual acquisition UTC \`observedAt\`, source SHA-256, exact LRL official URL, documented service years and districts and where necessary an LRL-declared nickname are checked. A candidate name/district match from an election result alone is never sufficient. A website link alone does not prove original 2022 filing website metadata.

The one-time internal audit job does the following: retrieves the original publicly acquired official service directory HTML+dated manifest, recomputes SHA-256 against that source receipt, reparses independent Senate terms, filters and validates all named original issue lead records, preserves separately supported historical page capture dates, and sets **2026-10-10** as the fallback date when only that contemporary publisher HTML was actually retrieved.

Artifact schema: \`senate-ever-served-dated-campaign-issue-source-leads-2021-25-v1\` report generated by \`src/evidence/senate-only-dated-campaign-issue-leads.ts\`; CLI at \`scripts/audit-senate-only-dated-campaign-issue-leads-offline.ts\`. Output is a single non-overwriting \`0600\` JSON artifact. No credentials, Neon, Vercel, external new sources, model/serving changes or production database use.

The associated historical **2022 original candidate-owned campaign website acquisition** is a separate #864 PR. It may produce more authenticated 2022 snapshots, but none should enter this ledger until independently verified as a dated, candidate-authored issue statement and the named person passes the same LRL Senate service gate.
